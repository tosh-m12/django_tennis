# データ集計表＋名簿 入出力・クレンジングツール 設計

> 管理者がデータ集計表/名簿を Excel・CSV でダウンロードし、表計算で名寄せ・整理・編集して
> アップロードすると DB に反映する「データクレンジング」機能。構造変更を意図的に許すため、
> 安全の柱は **スナップショット必須 ＋ 差分プレビュー→確定 ＋ atomic ＋ 監査ログ**。

## 決定事項（ユーザー合意済み）

- 形式: **Excel(.xlsx) と CSV束(ZIP) の両対応**（ダウンロード/アップロードとも）
- スコープ: 出欠 / 共通フラグ / 固有フラグ（値）＋ 名簿（roster）＋ フラグ定義の整理
- 反映: **差分プレビュー → 確定の2段** → `transaction.atomic()` → 適用前スナップショット ＋ `AuditLog`
- 人: 追加は不可。**削除＝完全削除（物理削除・復元不可）**。固定メンバー/試合履歴ありは**警告の上で強制**
- 名簿で編集可能: **固定/非固定・表示順(member_no)** のみ（表示名・クラスは読み取り専用）
- **名寄せ（統合）対応**: 名簿の `統合先` 列で重複を1人に集約
- 統合時の同一イベント出欠競合: **ファイルの記述を優先**（正行の値→無ければ従行の値）
- **フラグ定義の整理（削除/リネーム/統合）も対象**

## ファイル構成

| シート/CSV | 編集可能 | 読み取り専用（同定用） |
|---|---|---|
| `メタ` | （なし） | club_id・期間・生成時刻・snapshotトークン |
| `名簿` | 固定/非固定・表示順(member_no)・`統合先`列・`操作`列(=削除) | 行キー `m:<member_id>`・表示名・クラス |
| `出欠` | セル値（参加/不参加/未定/空） | 行キー・列ヘッダ `event:<id>` |
| `共通フラグ×N` | セル値（✓ または 0-9） | 行キー・列 |
| `固有フラグ×N` | セル値（✓ または 0-9） | 行キー・列 |
| `フラグ定義` | 名前(リネーム)・`統合先`・`操作`(=削除) | 定義キー・scope |

- 行キー: メンバー=`m:<member_id>` / ゲスト=`g:<ep_id>`。突合は**名前ではなく安定ID**。
- Excel は同定列・ヘッダ・メタを**セルロック**、値セルに**入力規則(ドロップダウン)**。

## アップロード適用順（1つの `atomic` 内・プレビュー確定後）

1. **名簿フィールド編集**: 固定 / member_no を反映（`unique(club, member_no)` 競合は検証で拒否）
2. **セル値編集**: 出欠・フラグを反映（既存メンバーに記録が無いイベントは参加記録を新規作成。**人の新規追加はしない**）
3. **フラグ定義整理**: リネーム → 統合（`ParticipantFlag` を統合先へ付替、`unique(ep, def)` 競合は値マージ）→ 削除（CASCADE）
4. **メンバー名寄せ（統合）**: `統合先` の重複を正へ集約。EP / フラグ / 対戦表 `MatchSchedule.schedule_json` の ep_id を付替。同一イベント競合の出欠は「ファイル記述優先」。重複メンバー削除
5. **メンバー完全削除**(`操作=削除`): Member ＋ EventParticipant を物理削除（`ParticipantFlag` は CASCADE）、`schedule_json` から ep_id を除去。固定/履歴ありは警告の上で強制
6. 適用前**スナップショット保存** → 適用後 **AuditLog 記録**

## DB を壊さないためのガード

- 全件検証 → **atomic**（部分適用なし） / 値ホワイトリスト
- **安定 ID で突合**（名前非依存） / **snapshot トークンで楽観ロック**（DL 後に DB が変われば再 DL を要求）
- 破壊操作（削除・統合・定義削除）は**差分プレビューで別枠強調＋警告**、確定操作必須
- `unique` 競合・固定メンバー・試合履歴ありは警告
- **適用前スナップショット＝巻き戻し可能**、全操作を監査ログ
- 行数 / ファイルサイズ上限・ヘッダ厳格一致・公開/終了イベントの既存ロック（`_guard_participant_change`）踏襲

## 再利用する既存実装

- データ収集: `club_data` view（`tennis/views.py`）→ マトリクス構築を共通関数へ切り出して exporter と共有
- 書き込み: `update_attendance` / `toggle_participant_flag` / `set_participant_flag_value`（`tennis/views.py`）
- 監査: `AuditLog` モデル
- モデル: `EventParticipant`(attendance, member FK=SET_NULL, unique(event,member)) / `ParticipantFlag`(is_on,value, unique(ep,def)) / `Member`(is_fixed, member_no, unique(club,member_no)) / `ClubFlagDefinition` / `EventFlagDefinition`

## 技術・段階的リリース

- 依存: **openpyxl**（Excel）／標準ライブラリ + `zipfile`（CSV束）
- **フェーズ1**: 基盤 ＋ 出欠/フラグ値の DL ＋ UL（差分プレビュー→確定→atomic→スナップショット→監査）
- **フェーズ2**: 名簿編集（固定/順）＋ メンバー完全削除
- **フェーズ3**: 名寄せ統合 ＋ フラグ定義整理（最難・最危険。巻き戻し前提で最後）

## 既知のリスク

- 完全削除・統合は不可逆で履歴（戦績・対戦表）を改変しうる → スナップショット＆監査を必須に
- 作り込みの山: 差分プレビュー UI / 同定の頑健化 / 統合の競合処理（特に `schedule_json` 付替）
