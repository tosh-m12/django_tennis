## 0. 大方針

現行の **「ログイン無し・クラブ単位トークンURL・全員編集可」** をそのまま維持する（＝**A案**）。
メール導入は認証の追加ではなく、あくまで **URL紛失防止** と **フリーミアムの土台** として足す。

- 幹事 = アカウントではなく「**確認済み復旧メール＋幹事トークンを持つ人**」。
- 課金は個人ではなく **クラブ単位**。
- 設計思想（引き算・自明性・安全側に倒す・主役はデータ）を優先。特に**広告は思想の逆**なので規律を厳守（§4）。

## 1. 幹事メール登録（複数人対応・名簿から指名）

現行 `Club` は単一トークンのみ。ここに **複数の幹事＋復旧メール** を持たせる。

- 新テーブル **`ClubAdmin`**（`club` FK, `member` FK=**任意**, `email`(null可), `confirmed_at`, `created_at`）＝ クラブ 1 : 多。
  **これが「誰が幹事か＋復旧メール」の唯一の source of truth。**
- 確認トークンは Django signing（署名付きトークン）で発行し、追加テーブルは作らない。

### 1-1. 指名フロー（本人 → 他の幹事）

1. クラブ作成本人は作成時にメール登録済み（§2）＝ `member` 未紐付けの `ClubAdmin` 行。URL紛失しても復旧可。
2. 名簿の**幹事/メンバー ドロップダウン**（§1-2）で誰かを「幹事」にすると、その Member に紐づく `ClubAdmin` 行を作成（email はまだ空）。
3. 指名された幹事は後から**自分の詳細ページ**でメールを登録 → 確認メール → `confirmed_at` 確定。
4. 確認済みになれば、その人も復旧ページ・再送の対象になり **同等の復旧機能** を得る。

### 1-2. 設定ページ／メンバー管理セクションのUI

- 各メンバー行に **幹事/メンバー ドロップダウン**（＝ClubAdmin行の作成/削除を書く窓）。
- **「メール 済／未」バッジ**（`ClubAdmin.confirmed_at` の有無）。本人が未登録の幹事を一目で把握できる。
- 幹事メールの **一覧 / 追加 / 削除 / 再送**（小さく。説明文は足さない）。

### 1-3. 規律（守れば罠にならない）

1. **幹事に指名 ⇒ 強制 `is_fixed`。** 非固定は自動削除される（`views._run_member_auto_cleanup`）ので幹事が消えないよう固定。
2. **名簿統合時に引き継ぐ。** 同名統合（member_id 紐付け）で 幹事フラグ・`ClubAdmin`・email を残す。
3. **確認メール必須＋送信は確認済みのみ。** 誤登録・なりすまし防止（§3の鉄則と同じ）。
4. **最後の幹事は外せない。** 全員メンバー化で復旧不能になる事故を防ぐガード。
5. **指名できるのは全幹事**（本人限定にすると本人が消えたとき詰む。皆信頼された幹事）。

### 1-4. 認識合わせ（ログイン無しゆえの前提）

- **ドロップダウンは権限スイッチではない。** アクセスは従来通り**共有の幹事URL**。「幹事」指名＝メール登録の資格＋名簿の目印であって、URLを渡さなければ操作はできない。逆に「メンバー」化しても幹事URL保持者からは剥がせない。
- **「自分だけが自分のページで登録」は強制できない。** 実際は幹事URL保持者なら誰の詳細ページからでも登録可能。信頼された幹事内の運用として許容する前提。
- **鉄則：幹事URLは強い。任意アドレスへは絶対送らない。** 送信先は常に **確認済み `ClubAdmin.email` のみ**。

## 2. 新規クラブ作成時のメール必須

- 作成フォームで **メール必須**（＝最初の `ClubAdmin` を作成と同時に登録）。
- **ソフト確認**：確認前でも **クラブは即使える**。確認は「復旧を有効化する」条件に留める（低摩擦を殺さない）。
- **デモクラブ（`/demo`）は対象外**（使い捨て・自動削除のため）。
- **既存クラブ**：メール未登録のまま。強制はせず、幹事ページに **「復旧メール未登録」バナー** を出して後追い登録を促す。

## 3. URL復旧（リンク無しの公開ページ）★重要

紛失防止が成立する条件 = **リンクが無くても入れる入口**。クラブ画面内の「再送」ボタンは、押せる時点で既にURLを持っている＝空振りするため、**トークン不要の公開ページ**を用意する。

```
[公開ページ] URLを忘れた方はこちら
  └ メールアドレスを入力
      └ そのアドレスが確認済み ClubAdmin なら
          └ その登録アドレス宛にだけ 幹事URL + メンバーURL を再送
```

- 未登録・未確認アドレスには **何も起きない**（存在秘匿。「該当あれば送信」の定型応答のみ）。
- **レート制限**（同一メール/IP）でメール爆撃を防ぐ。
- メール文面で役割を明示：**幹事用＝あなた専用・共有禁止／メンバー用＝みんなに配ってOK**。

**メンバーは登録しない。** メンバーURLはクラブ共通1本で、幹事が配る運用（LINE等）のまま。個人ごとのメールは紛失防止に寄与しないため持たない（引き算）。

## 4. 広告（AdSense）

オーナー保有の AdSense アカウントを使用。無料クラブに表示、有料クラブは除去。

- **手動広告ユニットのみ。Auto広告は使わない**（Auto は操作領域に勝手に差し込む＝思想違反）。
- 出す場所 = **内容のあるページ（クラブ入口・集計/ランキング表示）**。
  **スコア入力・対戦表編集・出欠などの操作画面には出さない**（誤操作防止）。
- `club.is_paid` が真なら **AdSenseスクリプト自体を出力しない**（＝残骸ゼロの完全除去）。
- 注意：トークンURLはクローラー非到達 → 広告精度は落ちうるが表示は可能。実害小。

## 5. フリーミアム（クラブ単位課金）

- `Club` に **`is_paid`**（+ `paid_until` / `stripe_customer_id` / `stripe_subscription_id`）。課金はクラブに紐付け ＝ 「複数幹事のうち誰が払うか」問題を回避。
- **ログイン無しとの両立**：**Stripe Customer Portal のリンクを確認済み幹事メールへ送る**方式。アカウントを作らず課金・解約を管理できる（§1・§2のメールがここでも効く）。
- 解約等は幹事メール宛ポータルリンクで誰でも操作可（＝全員が信頼された幹事）。
- 有料プランは **単一ティア**（引き算）。

## 6. 無料／有料の線引き

> **無料＝クラブを回す（入力・運営）／有料＝溜めたデータから価値を引き出す（戦績・分析・履歴・出力）**

| 区分 | 無料 | 有料 |
|---|---|---|
| 運営 | イベント・出欠・対戦表・**スコア入力** | — |
| 戦績 | 当日結果・簡単な合計まで（ティーザー） | 累計ランキング・勝敗記録・選手別戦績 |
| 分析 | — | 高度集計・選手別グラフ・トレンド |
| 履歴 | — | バックアップ／復元 |
| 出力 | — | xlsx / CSV / 取り込み |
| 広告 | AdSense 表示 | 除去 |

**原則1：スコア入力は無料のまま。** 入力を塞ぐと運営が回らず、データも溜まらず有料分析の価値も生まれない。**入れさせて、引き出す所で課金**。

**原則2：戦績はティーザー。** 全部隠すと無料クラブは魅力を感じる前に離脱する。無料は当日結果までチラ見せ、**累計・選手別・グラフ・履歴を有料で解放**。

## 7. データモデル追加（案）

| 変更 | 内容 |
|---|---|
| 新規 `ClubAdmin` | `club` FK / `member` FK(**任意**) / `email`(null可) / `confirmed_at` / `created_at`。1クラブ多。**幹事の唯一の真実。** |

既存 `AuditLog`（個人非特定で設計済み）を **履歴バックアップ/復元** に流用。既存 `data_export.py` はそのまま **有料ゲート** を噛ませるだけ。
